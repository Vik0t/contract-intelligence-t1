# Контрольный набор ПМИ для v1.0.0

Это исходный замороженный синтетический набор от 27 октября 2026 года, использованный в отчёте и [HTTP-протоколе от 28 октября](../../docs/PMI_HTTP_2026-10-28.md). Файлы и эталоны перенесены в Git побайтно, без повторной генерации или изменения разметки. Все названия организаций и исполнителей вымышлены; пользовательских договоров здесь нет.

| Состав | Значение |
|---|---|
| Договоры | 36, каждый в PDF и DOCX: 72 файла |
| Development | 24 договора / 48 файлов |
| Holdout для оценки | 12 договоров / 24 файла: 8 простых, 4 нетиповых |
| Шаблоны | 3; варианты одного договора всегда в одной части |
| Эталоны и разбиение | `manifest.json` |
| SHA-256 манифеста | `fae9bf7b07e6664b395a264441bb974f9db5b843070ced74f713017194227f77` |
| Состояние ручной сверки | `pending_manual_review`, сохранено из исходного набора |

Манифест содержит эталоны номера, даты, сторон с ролями, суммы с валютой и SHA-256 каждого документа. `manifest.sha256` фиксирует сам манифест. Оценщик проверяет хеши выбранных файлов до первой обработки. Генератор — [tools/generate_acceptance_dataset.py](../../tools/generate_acceptance_dataset.py); для воспроизведения отчёта используйте уже сохранённые файлы, а не новую генерацию.

## Оценка через API

Запустите стенд `pmi-rules-v1` и получите токен отдельной испытательной учётной записи по [инструкции релиза](../../docs/RELEASE_v1.0.0.md). Из корня репозитория:

```bash
uv run --frozen python -m scripts.evaluate_acceptance \
  --dataset evals/pmi-control-v1 --split holdout \
  --profile pmi-rules-v1 --backend rules --transport http \
  --base-url http://127.0.0.1:8080/api \
  --review-policy issued \
  --output tmp/pmi-v1.0.0-http.json
```

Токен читается из `PMI_SESSION_TOKEN`, а не из аргументов команды. Выходной файл должен отсутствовать: прежние протоколы не перезаписываются.

В JSON раздел `metrics.attributes` содержит `tp`, `fp`, `fn`, `precision` и `recall` для каждого из четырёх атрибутов; `atypical` — отдельные результаты нетиповых форм. Единица оценки — договор: результат должен быть правильным в обоих форматах. Неверное выданное значение даёт FP и FN; `needs_review` учитывается как выданный ответ при `issued`. Корректное отсутствие не увеличивает TP. Подробные правила — [ACCEPTANCE.md](../../docs/ACCEPTANCE.md).

Результат на этих синтетических формах относится к профилю `rules`. Он не измеряет качество Qwen/NuExtract, сводок, юридического анализа или произвольных реальных договоров. Ручная сверка эталонов и решение комиссии оформляются отдельно.

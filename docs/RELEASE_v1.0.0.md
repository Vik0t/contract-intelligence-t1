# Релиз v1.0.0

Дата: 29 октября 2026 года, Asia/Novosibirsk. Исходники фиксируются аннотированным тегом Git **`v1.0.0`**. Версии Python-пакета, OpenAPI и frontend — `1.0.0`.

Релиз включает текущие исправления реестра и карточки договора: корректное обновление очереди, защиту правок оператора от запоздалых ответов, восстановление после ошибок, синхронизацию выхода между вкладками, редактирование срока текстом, копирование и экспорт полей. Сохраняются шрифты ALS Hauss, белые рабочие поверхности и просмотр настоящих PDF/DOCX/изображений. Повторная обработка после ошибки чтения использует сохранённый оригинал. Подробный браузерный проход — [UX-аудит](UX_AUDIT_2026-10-28.md).

## Контрольный набор

[evals/pmi-control-v1](../evals/pmi-control-v1/README.md) содержит исходные 36 вымышленных договоров в двух форматах, манифест с эталонами и SHA-256. Разбиение не менялось: 24 development / **12 holdout**. Контрольная часть — 8 простых и 4 нетиповых договора, всего 24 PDF/DOCX.

## Воспроизведение из чистого клона

Нужны Git, Docker с Compose v2 (поддержка `!reset`), Python 3.12/3.13 и uv. Для четырёх атрибутов GPU, веса моделей и внешний API не требуются. Сборка скачивает зависимости; обработка договоров выполняется локально.

После публикации тега в `origin`:

```bash
git clone --branch v1.0.0 https://github.com/Vik0t/contract-intelligence-t1.git
cd contract-intelligence-t1
git describe --tags --exact-match
uv sync --frozen
cp .env.rules.example .env.rules
```

В `.env.rules` замените `POSTGRES_PASSWORD` на случайный hex-пароль. Для уже существующей БД используйте её действующий пароль. Отдельное имя проекта ниже создаёт отдельные volumes и не использует рабочую базу приложения. Порт по умолчанию — 8080; при необходимости измените `HTTP_PORT` и адреса в командах.

```bash
docker compose -p t1-pmi-v1 --env-file .env.rules -f compose.yaml -f compose.rules.yaml build backend frontend
docker compose -p t1-pmi-v1 --env-file .env.rules -f compose.yaml -f compose.rules.yaml up -d --wait
curl --fail http://127.0.0.1:8080/api/runtime/profile
```

Ответ должен содержать `profile.id=pmi-rules-v1`. Фиксируются CPU/rules, нативный DOCX, текстовый PDF, PostgreSQL, автоматическое извлечение, отключённые OCR и внешние вызовы. Образ собирается из выбранного тега; готовые образы в реестр в этой операции не публикуются.

Для автоматического прогона создайте отдельную случайную испытательную учётную запись. Команда получает токен в переменную окружения; пароль и токен не печатаются в терминал и не включаются в отчёт:

```bash
export PMI_SESSION_TOKEN="$(uv run --frozen python - <<'PY'
import secrets
import httpx

username = 'pmi' + secrets.token_hex(6)
password = secrets.token_hex(24)
with httpx.Client(base_url='http://127.0.0.1:8080/api/', trust_env=False) as client:
    response = client.post('auth/register', json={
        'username': username, 'email': username + '@example.org', 'password': password,
    })
    response.raise_for_status()
    response = client.post('auth/login', json={'username': username, 'password': password})
    response.raise_for_status()
    print(response.json()['session_token'])
PY
)"

uv run --frozen python -m scripts.evaluate_acceptance \
  --dataset evals/pmi-control-v1 --split holdout \
  --profile pmi-rules-v1 --backend rules --transport http \
  --base-url http://127.0.0.1:8080/api \
  --review-policy issued \
  --output tmp/pmi-v1.0.0-http.json

unset PMI_SESSION_TOKEN
```

Оценщик не перезаписывает существующий результат: для повторного прогона задайте новый `--output`. Он проверяет хеши входов, загружает оба формата, ожидает очередь, читает сохранённые поля и текст, сверяет оригиналы и повторное чтение. Это не замена ответов готовыми эталонами.

В отчёте `metrics.attributes` содержит TP/FP/FN, precision и recall по номеру, дате, сторонам и сумме; `atypical` — нетиповые формы; `metrics.typical_all_four_rate` — долю простых договоров со всеми четырьмя верными атрибутами. Договор засчитывается только при правильном результате в обоих форматах. Политика `issued` включает значения `needs_review`; неверный выданный ответ даёт FP и FN.

После испытаний можно остановить только этот стенд, сохранив данные:

```bash
docker compose -p t1-pmi-v1 --env-file .env.rules -f compose.yaml -f compose.rules.yaml stop
```

## Область результата

Профиль поставки четырёх обязательных атрибутов — **`pmi-rules-v1`**. Qwen/NuExtract, фотографии, сводка и юридические риски относятся к отдельным конфигурациям и не оцениваются этой командой. Прежние результаты от 28 октября сохранены в [отдельном протоколе](PMI_HTTP_2026-10-28.md) со своими хешами исходников.

Эталоны сохраняют статус `pending_manual_review`. Создание релизного тега не заменяет ручную сверку, испытания на НГУ, полный протокол А-1…А-18 и решение комиссии; `formal_acceptance_ready` остаётся `false` до выполнения условий оценщика.
